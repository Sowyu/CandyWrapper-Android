# Design

CandyWrapper for Android copies T3 Code's desktop app, adapted to a phone. T3's sidebar is the main navigation. The macOS CandyWrapper (`~/CandyWrapper`) already copies T3 to pixel fidelity, so its assets are the source of truth here: `docs/design-tokens.md` for values, `design/component-reference/` and `design/reference/` for how each component and screen looks, and `Packages/CandyKit/Sources` for how it was built. T3's own web source is in the history of `~/t3pretzel` (`git show 5140e6c8e9^:apps/web/src/...`).

## Where it lives

- `ui/Theme.kt` holds the palette (light, dark and the `[data-app-sidebar]` subtree, copied from design-tokens.md), the type scale, radii and motion.
- `ui/Icons.kt` is generated by `scripts/gen-icons.py` from CandyWrapper's `IconData.generated.swift`: lucide 0.564.0, the version T3 pins, plus the Claude and OpenAI glyphs. To add an icon, add its name to `scripts/icon-names.txt` and run the command in the script's header.
- `ui/Kit.kt` has T3's controls: button, icon button, input, menu popup and items, bottom dialog, alert, badge, card, empty state, the project monogram and `ProjectIcon` (T3's `ProjectFavicon`: the chosen icon, else the icon file from the computer, else the monogram, in every place a project shows).
- `ui/Shell.kt` is the frame: the sidebar as a drawer on phones, beside the thread from 840dp.
- `ui/Sidebar.kt` is T3's sidebar (`Sidebar.tsx` and `sidebar/SidebarThreadRow.tsx`): one flat list of pinned and active cards over the Snoozed and Settled shelves. Its rules live in core `sidebar/SidebarLogic.kt`, after `Sidebar.logic.ts` and client-runtime `threadInbox.ts` for the Working shelf.
- `ui/LegacySidebar.kt` is T3's project tree (`LegacySidebar.tsx`), shown when Settings > Legacy sidebar is on. Both sidebars share the machine switcher, alerts and footer in `ui/SidebarChrome.kt`.
- `ui/Timeline.kt`, `MarkdownView.kt`, `Composer.kt` and `Pending.kt` are the chat view, `.chat-markdown`, the composer and its trays.

## Phone adaptation

- Sizes follow T3's own touch breakpoint where it has one: buttons are `h-9` with `text-base`, menu items `min-h-8 text-base` with 18dp icons, inputs 36dp. Every control keeps a 44dp touch target.
- Chat text and the composer are 15sp; T3 uses `text-sm` (14). Sidebar time labels are 11sp; T3 uses `text-3xs` (10).
- Sidebar rows are 36dp in a 40dp slot; T3's are `h-8` (32).
- T3's mobile sidebar is `100vw - 12px`. Here it is the window minus 56dp, at most 360dp, so a strip of the thread stays to tap it closed.
- A swipe from the left edge opens the sidebar. With gesture navigation Android keeps that edge for Back, so the app claims only the middle 200dp of it (the most Android allows).
- Below 520dp the composer folds mode and access into ⋯, as T3's `CompactComposerControlsMenu` does on narrow windows.
- Dialogs sit on the bottom edge with rounded top corners, as T3's do on phones (`bottomStickOnMobile`).

## Differences from T3

| T3 | Here | Why |
|---|---|---|
| T3 wordmark and stage art in the sidebar header | The computer switcher | The phone talks to several computers; the switcher is what the header is for here |
| `dialog-backdrop` and `dropdown-glass` blur | Solid colours: the backdrop tint and `--popover` | A live blur repaints every frame under it; CandyWrapper made the same substitution |
| Sidebar `surface-grain` texture | Flat `--sidebar` | A full-height texture costs memory and fill for a 3.5% effect |
| Working status pulses (`animate-status-pulse`) | A static dot | Nothing repaints while idle |
| Blue send button | CandyWrapper's plum | The owner's choice for CandyWrapper (macOS design.md) |
| Code blocks show pierre's file-type icon | A small mono language tag | No file-type icon set yet |
| Inline code has a border and radius | A tinted background | Compose text spans cannot draw borders |
| Archived threads live in Settings | An archive toggle in the sidebar footer | Asked for in the brief; it reads `orchestration.getArchivedShellSnapshot` |
| Hover actions on rows (Settle, Snooze, Unpin, Woke) | Long press opens the row's menu, which also has Pin, Wake now and Un-settle | No hover on touch |
| Drag rows to pin, reorder or settle | Pin, Settle and Snooze from the row menu; no reordering | Long press is taken by the menu; keyless pins keep T3's newest-first order |
| Snooze presets and a custom time | The presets only | A date picker sheet is a later step |
| Search covers titles and message content | Titles only | Content search is a server query this client does not send yet |
| The project filter has a search field | A plain list | Popups here do not host text fields yet |
| Project grouping follows the grouping setting, and scratch projects share "No project" | Always by repository; scratch projects keep their own title | The setting is per desktop client; the scratch root comes from a config the cache does not keep |
| Sections follow the server's capabilities | Sections follow the thread's fields; only the actions check capabilities | The capabilities arrive with `server.getConfig`, after a cold start has drawn the list from the cache |
| A remote thread shows a machine icon with a tooltip | With All machines each card names its machine | No tooltips on touch |
| The draft block, pull request and terminal badges on cards | Not built | They need data the shell does not carry here |
| The Working section setting syncs with the desktop client settings | Settings > Sidebar > Working section, stored on the phone, off by default as in T3 and CandyWrapper | Client settings live in each client |
| The expanded image preview dims the page | A black full-screen viewer with pinch zoom, swipe down to close, Save and Share | A phone's photo viewer conventions; there is no pointer to zoom with |
| Stash with a keyboard shortcut; the list restores or deletes | Stash prompt in the composer's ⋯ on a phone (a bookmark button from 520dp); each row also has Swap, which stashes the draft and restores the prompt in one step | No keyboard on a phone; swap was asked for |
| The stash lives in browser storage, images as data URLs | `prompt-stash/stash.json` in the app's files, replaced atomically, images as files beside it, as CandyWrapper stores them | A phone keeps images as files |
| Add project in the thread header | Not built | Adding a project needs a folder on the computer |
| Parking the open thread with no card left opens a new thread | Opens the empty state, with the sidebar | A phone lands in the sidebar to pick the next one |
| A lucide project icon draws that icon in its colour | The monogram in the icon's colour | The app carries only the lucide icons it uses; T3's own mobile app does the same |
| SVG project icons draw in the browser | A small SVG reader draws paths, shapes, solid fills and strokes; a gradient paints as its average colour, clip paths and masks are skipped; an SVG it cannot read, and `.icns` files, keep the monogram | Android has no SVG decoder and the dependencies stay fixed |
| The machine switcher (not in T3) | Lists All machines first when there are several, and starts there | The phone reads several computers; T3's sidebar always merges every connected environment |

## Redesign (Experimental)

Settings > Appearance > Redesign is CandyWrapper's Redesign theme on the Mac (internally "Dither", after Capy's desktop app). It is off by default, stored on the phone, and switches live. Off, every screen draws exactly the T3 look above; each Redesign branch checks `Candy.redesign`.

- `ui/Redesign.kt` holds Capy's palette (`capyColors`, from `capyDarkColors` and `capyLightColors` in ThemePalette.swift, lines as overlays as WindowGlass.frosted makes them) and the eight accents from `DitherAccent`.
- `Radius` follows `DitherChrome.radius` under Redesign: controls 8, cards, popovers and bubbles 12, the composer 16.
- `ui/DitherArt.kt` is `DitherArt.render`: brightness-only ordered dither in three strengths, the 98 reach and the bottom fade. `ui/RedesignPanel.kt` draws it behind the main panel with the page's scrim (new thread 0, an open thread the Background dim, Settings 0.8, other pages 0.92) and the band colour fading down from the top.
- `ui/HugeIcons.kt` is generated by `scripts/gen-hugeicons.py` from CandyWrapper's IconDataHugeicons.generated.swift. `Icon` swaps a lucide glyph for its Hugeicons one at the Mac's sizes: 14 in 11 to 14 boxes, 16 in 15 and 16 boxes, one 1.2dp stroke, the duotone tint only above 16.
- `ui/RedesignKit.kt` has the pills (30dp, 8dp corners, frost, rim, shadow), the dot grid, the waiting pill, the machine row, the header pill and the provider card.

| Mac Redesign | Here | Why |
|---|---|---|
| Dithers the desktop picture, or a chosen file | Four pictures painted in code (Dusk, Lagoon, Ember, Meadow), or a photo from the system picker | Android hands an app the wallpaper only with a storage permission; no bundled image assets |
| Frosted panes blur the art live under them | The composer, pills and header pill draw a pre-blurred copy of the art, rendered once with it; message bubbles stay solid | A live blur repaints under a scrolling list every frame |
| The dot grid sweeps continuously while working | Each tick of the shared one-second ticker sends one 600 ms sweep, then it rests | The app's single-ticker rule: it stops when "Working for" stops |
| "Working for" rolls its digits and shimmers | The digits roll; no shimmer | The shimmer loops while idle on screen |
| A tab strip band with a slim header pill: cost, actions, terminal, diff totals, right panel | The thread header's ⋯ sits in a frosted pill with the last run's diff totals, which open its diff | A phone has no tab strip, terminal or right panel; the client has no token usage to price |
| Hover actions on rows | Long press opens the row's menu | No hover on touch |
| Sections and threads drag; Manual project order | Sections follow the sidebar's project order; no drag | Long press is taken by the menu |
| The model picker has search across the top and Manage on the card | Rail, card and models only | A phone lists a handful of models; popups here do not host text fields; there is no providers page |
| The machine row reads "machine · Worktree/Local" with a menu | The machine and its connection dot | The client does not read the checkout |
| The waiting pill names the subagent and offers Show | "Waiting", with Stop | The shell carries the Waiting status, not the subagents |
| Context ring and popover, cost pill, minimap, image gallery, subagent strip, window frame, tab strip, menu bar item, Orchestrator | Not built | They need data the client does not decode, or they are Mac-only |
| The e-mail on the provider card blurs until clicked | Blurs until tapped on Android 12 and later; shows as dots before | `Modifier.blur` needs RenderEffect |

## Motion

The shelves sit at the bottom of a short list, as T3's `mt-auto` does, through a list arrangement that only applies while the list fits.

Colour, press-scale (0.97) and chevron turns take T3's 150ms `cubic-bezier(.4,0,.2,1)`. Menus fade and scale in from 95% at their trigger over 150ms. Sheets and the drawer take 200ms. Nothing animates while the screen is idle.

## Screenshots

`./gradlew :app:recordRoborazziDebug` renders the components and full screens on Robolectric (SDK 35, native graphics) and writes the images to `app/src/test/snapshots`, in light and dark, at a 411x891dp phone and a 1280x800dp tablet. Redesign's shots are in `app/src/test/snapshots/redesign`. `./gradlew :app:verifyRoborazziDebug` compares against them. CI does not run them yet.
